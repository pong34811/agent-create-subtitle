## 2. จุดด้อยของ skill

- **ความรู้กระจาย 4 ที่ ไม่มีดัชนี** `create-subtitle` เป็นทางเข้าแต่ไม่ได้ผูกกับ `thai-subtitles-resolve` / `thai-proofread` / Mitr presets อย่างชัดเจนมาก่อน (แก้ในรอบนี้ด้วยตารางขั้นตอน)
- **`thai-subtitles-resolve` ยาว ~21 KB และปนหลายเรื่อง** (ASR, ตัดคำ, import, สไตล์ฐานข้อมูล, SFX/GIF) โหลดทีเดียวกินบริบทมาก ควรแยกส่วน SFX/BGM/GIF และส่วนแก้ style blob เป็น `references/`
- **ข้อความ Whisper ยังปนอยู่ใน SKILL หลัก** (ตั้งค่า transcribe, ติดตั้ง CUDA DLL) ทั้งที่ท่อหลักเป็น Gemini แล้ว ถูกติดป้ายว่า "ใช้เมื่อ Whisper เหมาะ" แต่ยังทำให้ agent สับสนได้
- **`thai-proofread` ไม่ผูกกับงานซับ** ไม่บอกว่าต้องรักษา timing, ข้อจำกัดความยาวต่อบรรทัด หรือให้ตรวจเฉพาะ cue ที่ `uncertain` และไม่มีขั้นตอนตรวจกับเสียง
- **`resolve-mitr-subtitle-presets` อ้างรีโปอื่น** (`agent-edite-davinci_resolve`) และเขียน SQLite ตรงเมื่อปิดโปรเจค เสี่ยงสูง ต้องมีการอนุมัติชัดเจนทุกครั้ง
- **description ยาวเกิน/สไตล์ไม่เท่ากัน** บาง skill มีเมทาดาทา Hermes เฉพาะตัวที่ Claude Code ไม่ใช้

## 3. จุดด้อยของโปรเจคเมื่อสั่ง agent สร้างซับไทย

1. **ไม่มีคำสั่งเดียวจบ** ท่อมี 6 ขั้นต่อกันด้วยมือ ผ่านล่ามคนละตัว (`python` 3.11 กับ `py -3.12`) ความผิดพลาดที่พบคือ dry run ผ่านแต่ `--apply` ล้ม ควรมีตัวรันรวมที่เลือกล่ามให้เอง
2. **ไม่มีคนตรวจกับเสียง** ซับทั้ง 49 ไทม์ไลน์เป็น `approved: false` agent บอกได้แค่ว่า "ผ่านเกณฑ์ตัวเลข" ไม่ได้ว่า "ตรงเสียง" ยังไม่มีขั้นตอนสุ่มฟังหรือรายงาน cue ที่ต้องตรวจก่อน
3. **คุณภาพไม่คงที่** ซับมาจาก 7 โมเดล เพราะโควตาฟรีรายวันหมดระหว่างทาง (9 ไฟล์เป็น `gemini-2.5-flash` ที่อ่อนสุด) ควรบันทึกโมเดลต่อไฟล์เป็นข้อมูลตรวจสอบ และมีโหมด "ทำซ้ำเฉพาะไฟล์ที่ใช้โมเดลอ่อน"
4. **14 cue ถูกปรับเวลา** (`timestamp_beyond_duration`, `overlap_merged`) ข้อความครบแต่เวลาไม่ได้มาจากเสียงโดยตรง ยังไม่มีการเทียบกับ VAD หรือ forced alignment
5. **ไม่มีเกณฑ์สไตล์ซับเดียว** ท่อเก่าตัดเป็นการ์ด 1-4 คำ ท่อใหม่ตัดเป็นวลีธรรมชาติ ผู้ใช้ต้องบอกเอง ถ้าไม่บอก agent เดาเอง
6. **ผูกกับ Resolve และ Windows** ไม่มีทางส่งออกซับอย่างเดียวที่ไม่แตะ Resolve ได้ง่ายนอกจากข้ามขั้น import และไม่มีตัวทดสอบที่ไม่ต้องเปิด Resolve ยกเว้นชุด unit test ที่ mock
7. **ความลับและโควตา** ใช้คีย์ Google ตัวเดียว ไม่มีการจำกัดค่าใช้จ่ายหรือแจ้งเตือนเมื่อเปลี่ยนไปใช้โมเดลที่อ่อนกว่า
8. **ขาดคำศัพท์เกมและชื่อเฉพาะแบบกำหนดได้** ชื่อเกม/ตัวละครถูกเดาจากเสียง ควรมีไฟล์คำศัพท์ต่อโปรเจคแล้วส่งเข้า prompt
9. **ไม่มี CI** ชุดทดสอบ 32 ตัวรันด้วยมือเท่านั้น และไม่มีการตรวจว่า skill ใน `.agents` กับ `.claude` ตรงกัน (เพิ่ม `sync_skills.py --check` แล้ว แต่ยังไม่ผูก hook)
10. **หลักฐานการรัน (`runs/`) ใหญ่ ~967 MB ในเครื่อง** ส่วนที่ track ใน git มีขนาดเล็ก แต่ควรมีนโยบายเก็บ/ล้างต่อรอบงาน

## 4. สิ่งที่ยังค้าง (แนะนำลำดับถัดไป)

1. ตัวรันรวม `scripts/run_pipeline.py` (เลือกล่าม, dry-run ก่อนเสมอ, สรุปผล)
2. ขั้นตอนตรวจกับเสียง: สุ่ม cue ที่ `uncertain` และ cue ที่ถูกปรับเวลา แล้วทำรายงานให้คนอนุมัติ
3. ไฟล์คำศัพท์ต่อโปรเจค ส่งเข้า prompt ถอดเสียง
4. แยก `thai-subtitles-resolve` เป็น SKILL หลักสั้น + references
5. ผูก `sync_skills.py --check` กับ pre-commit hook
