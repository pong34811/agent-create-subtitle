## 🚀 Release v0.5.0 — ตัวรันรวม ตัวตรวจเสียง และผลทดสอบกับ Gemini/Resolve จริง

ต่อจาก v0.4.0: ทำงานค้างที่รีวิวไว้ และ **ทดสอบกับของจริง** ซึ่งเจอบั๊กที่ unit test ไม่เห็น

---

### 🔎 สิ่งที่ทดสอบกับของจริงแล้วพบ

1. **Gemini API** (ไทม์ไลน์ 36, `gemini-3.5-flash`): ถอดเสียงสำเร็จ ข้ามโมเดลที่ตอบ 503 ได้เอง
   แต่ผลต่างจากรอบเดิมของโมเดลเดียวกันกับเสียงเดียวกัน — **ข้อความต่าง และเวลาต่างได้ราว 1.5-2 วินาที**
   ผลถอดเสียงจึงไม่ซ้ำเดิม ต้องมีคนอนุมัติทุกชุด
2. **Resolve** (อ่านอย่างเดียว): 49/49 ไทม์ไลน์มี subtitle track และจำนวน cue ตรงกับ SRT
   แต่ **ID ไทม์ไลน์ใน manifest ไม่ตรงกับของจริงเลย** (Resolve ออก ID ใหม่) สคริปต์เดิมจึงจะรายงานว่า
   "ไม่พบไทม์ไลน์" ทั้งหมด
3. `gemini_direct_transcribe.py` ล็อก manifest ไว้ที่ 49 รายการพอดี ใช้กับ run อื่นไม่ได้

### 🛠️ สิ่งที่เปลี่ยนแปลง

- **`scripts/run_pipeline.py`**: ทางเข้าเดียว `status|transcribe|cues|verify|import` เลือกล่ามให้เอง
  (`py -3.12` สำหรับ Resolve, venv 3.11 สำหรับ pythainlp) และ `import` เป็น dry run เสมอถ้าไม่ใส่ `--apply`
- **`scripts/verify_cues_audio.py`**: เทียบทุก cue กับพลังงานเสียงย่านพูด ไม่ใช้โมเดล/เน็ต
  ผลรัน 49 ไทม์ไลน์: 963 cue ติดธง **204 (21%)** — เป็นรายการ "ควรฟังก่อน" ไม่ใช่ข้อผิดพลาด
- **แก้การหาไทม์ไลน์**: ใช้ ID ก่อน แล้วถอยไปใช้ชื่อที่ไม่ซ้ำ (`pick_timeline`) — dry run กับ Resolve จริง
  ได้ skip 49 / ไม่พบ 0 (ไม่ซ้อนซับ)
- **เอาการล็อก 49 ออก** จากสคริปต์ถอดเสียง 2 ตัว และ `import_subtitles_resolve.py` / test ไม่ใช้ path แข็งอีก
- เพิ่ม **`GLOSSARY.md`** และ **`docs/adr/0001-gemini-asr-over-whisper.md`**
- อัปเดต skill `create-subtitle`, `AGENTS.md`, `docs/REVIEW-th.md`
